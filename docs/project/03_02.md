
# A과정 3장 2교시 — Apache 설치 및 서비스 관리

## 1. 학습 환경

- OS: Ubuntu Server 24.04 LTS
- WEB 서버: Apache HTTP Server
- 서버: WEB01 (192.168.111.141)
- 사용 포트: TCP 80

## 2. Apache 설치

```bash
sudo apt update
sudo apt install -y apache2

apache2 -v
dpkg -l apache2
```

- `apt update`: 패키지 목록 갱신
- `apt install`: 패키지 설치
- `-y`: 설치 확인에 자동 동의
- `apache2 -v`: Apache 버전 확인
- `dpkg -l apache2`: 패키지 설치 여부 확인

## 3. Apache 서비스 관리 (systemd)

```bash
sudo systemctl status apache2
sudo systemctl start apache2
sudo systemctl stop apache2
sudo systemctl restart apache2
sudo systemctl reload apache2

sudo systemctl enable --now apache2

systemctl is-active apache2
systemctl is-enabled apache2
```

| 명령어 | 역할 |
|---|---|
| start | 서비스 시작 |
| stop | 서비스 중지 |
| restart | 서비스 재시작 |
| reload | 설정 재적용 |
| enable | 부팅 시 자동 시작 |
| --now | 자동 시작 설정과 함께 즉시 실행 |
| is-active | 현재 실행 상태 확인 |
| is-enabled | 부팅 시 자동 시작 여부 확인 |

**핵심:** `enable`은 자동 시작 설정이고, `start`는 현재 서비스를 실행하는 명령이다.

## 4. TCP 80 포트 확인

```bash
sudo ss -lntp '( sport = :80 )'
```

옵션:
- `-l`: LISTEN 상태
- `-n`: 숫자 주소 및 포트
- `-t`: TCP
- `-p`: 프로세스 정보

수신 주소 차이:
- `0.0.0.0:80`: 모든 IPv4 로컬 인터페이스에서 수신
- `127.0.0.1:80`: 루프백 주소에서만 수신

서비스가 실행 중이어도 외부에서 TCP 80 포트에 접근할 수 있는지는 별도로 검증해야 한다.

## 5. HTTP 응답 검증

```bash
# 로컬 HTTP 요청
curl -i http://127.0.0.1/

# 실제 서버 IP로 요청
curl -i http://192.168.111.141/

# 응답 헤더만 확인(HEAD 요청)
curl -I http://192.168.111.141/

# HTTP 상태 코드 확인
curl -sS -o /dev/null -w '%{http_code}\n' http://192.168.111.141/
```

주요 옵션:
- `-i`: 응답 헤더와 본문 출력
- `-I`: HEAD 요청으로 헤더 확인
- `-s`: 진행 정보 출력 최소화
- `-S`: 오류 메시지 출력
- `-o /dev/null`: 응답 본문 버리기
- `-w`: 원하는 출력 형식 지정

정상적인 기본 페이지 응답은 일반적으로 HTTP 200이다.

## 6. 기본 DocumentRoot

Ubuntu Apache 기본 사이트의 문서 디렉터리:

```text
/var/www/html/
```

테스트 파일 생성 및 요청:

```bash
echo "Apache WEB01 test OK" | sudo tee /var/www/html/lesson2.txt

curl -i http://127.0.0.1/lesson2.txt
```

예상 응답:

```text
HTTP/1.1 200 OK

Apache WEB01 test OK
```

실습 파일 삭제:

```bash
sudo rm /var/www/html/lesson2.txt
```

DocumentRoot는 웹 서버가 정적 파일을 제공할 때 기준으로 사용하는 디렉터리다.

## 7. Apache 주요 경로

| 경로 | 용도 |
|---|---|
| /etc/apache2/apache2.conf | Apache 기본 설정 |
| /etc/apache2/ports.conf | 수신 포트 설정 |
| /etc/apache2/sites-available/ | VirtualHost 설정 |
| /etc/apache2/sites-enabled/ | 활성화된 사이트 |
| /etc/apache2/mods-available/ | 사용 가능한 모듈 |
| /etc/apache2/mods-enabled/ | 활성화된 모듈 |
| /var/www/html/ | 기본 DocumentRoot |
| /var/log/apache2/ | 로그 디렉터리 |

## 8. 설정 문법 및 로그 확인

설정 문법 검사:

```bash
sudo apache2ctl configtest
```

정상 결과:

```text
Syntax OK
```

Access Log:

```bash
sudo tail -n 20 /var/log/apache2/access.log
```

Error Log:

```bash
sudo tail -n 20 /var/log/apache2/error.log
```

실시간 Access Log:

```bash
sudo tail -f /var/log/apache2/access.log
```

systemd 서비스 로그:

```bash
sudo journalctl -u apache2 -n 30 --no-pager
```

**중요:** `Syntax OK`는 설정 문법이 정상이라는 의미이며, 실제 HTTP 서비스 정상 동작까지 보장하지 않는다.

## 9. UFW 방화벽

방화벽 상태 확인:

```bash
sudo ufw status verbose
```

VMware 내부 네트워크에서 HTTP 허용:

```bash
sudo ufw allow from 192.168.111.0/24 to any port 80 proto tcp
```

규칙 확인:

```bash
sudo ufw status numbered
```

실제 운영에서는 필요한 출발지 네트워크만 허용하도록 접근 범위를 제한한다.

## 10. Apache 장애 대응

### Apache 서비스 실행 실패

```bash
sudo systemctl status apache2
sudo apache2ctl configtest
sudo ss -lntp '( sport = :80 )'
sudo journalctl -u apache2 -n 50 --no-pager
```

주요 원인:
- Apache 설정 문법 오류
- TCP 80 포트 충돌
- 파일 및 디렉터리 권한 문제
- 모듈 설정 오류

### Apache는 실행 중이지만 외부 접속 실패

```bash
systemctl is-active apache2
sudo ss -lntp '( sport = :80 )'
curl -i http://127.0.0.1/
curl -i http://192.168.111.141/
sudo ufw status verbose
```

서버 내부 HTTP 요청은 성공하지만 Windows에서만 실패하면 수신 주소, VMware 네트워크, UFW 규칙 등을 우선 확인한다.

## 11. Apache 정상 동작 검증 순서

1. 패키지 설치 확인: `dpkg -l apache2`
2. 서비스 실행 확인: `systemctl status apache2`
3. TCP 80 LISTEN 확인: `ss -lntp`
4. HTTP 응답 확인: `curl -i`
5. 외부 PC 접속 확인: 웹브라우저 또는 TCP 연결 검사
6. 로그 확인: `tail`, `journalctl`

**설치 성공 ≠ 서비스 실행 성공 ≠ 포트 연결 성공 ≠ HTTP 응답 성공**

## 핵심 요약

- Apache는 Ubuntu에서 `apache2` 패키지로 설치한다.
- `systemctl`로 서비스를 시작·중지·재시작·관리한다.
- `ss`로 TCP 80 포트의 수신 상태를 확인한다.
- `curl`로 실제 HTTP 응답을 검증한다.
- `apache2ctl configtest`로 설정 문법을 검사한다.
- Access Log와 Error Log를 통해 요청과 오류를 분석한다.
- 장애 시 서비스 상태 → 포트 → HTTP 응답 → 방화벽·네트워크 순서로 확인한다.
