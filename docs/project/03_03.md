
# A과정 3장 3교시 — Apache 설정 파일 및 VirtualHost

## 1. 학습 목표

- Apache 설정 파일 구조 이해
- VirtualHost 생성 및 활성화
- ServerName, DocumentRoot, Directory 지시어 이해
- 설정 문법 검사 및 HTTP 응답 검증
- VirtualHost 설정 오류 분석

### 실습 환경

- OS: Ubuntu Server 24.04 LTS
- WEB 서버: Apache HTTP Server
- IP: 192.168.111.141
- 실습 도메인: web01.test
- 웹 디렉터리: /var/www/web01/public

---

## 2. Apache 설정 파일 구조

| 경로 | 역할 |
|---|---|
| /etc/apache2/apache2.conf | Apache 전역 설정 |
| /etc/apache2/ports.conf | 수신 포트 설정 |
| /etc/apache2/sites-available/ | VirtualHost 설정 파일 보관 |
| /etc/apache2/sites-enabled/ | 활성화된 사이트 설정 |
| /etc/apache2/mods-available/ | 사용 가능한 모듈 |
| /etc/apache2/mods-enabled/ | 활성화된 모듈 |
| /var/www/ | 웹 콘텐츠 디렉터리 |
| /var/log/apache2/ | Apache 로그 디렉터리 |

### 설정 확인 명령어

```bash
ls -l /etc/apache2/
ls -l /etc/apache2/sites-available/
ls -l /etc/apache2/sites-enabled/

sudo cat /etc/apache2/ports.conf
sudo cat /etc/apache2/sites-available/000-default.conf
```

### 핵심 개념

- sites-available: 사이트 설정 파일이 존재하는 곳
- sites-enabled: 활성화된 사이트 설정을 가리키는 심볼릭 링크가 있는 곳

설정 파일을 생성했다고 자동으로 적용되는 것은 아니다.

---

## 3. VirtualHost란?

하나의 Apache 서버에서 서로 다른 웹사이트를 구분해 운영할 수 있도록 하는 설정이다.

예시:

```text
shop.example.com → /var/www/shop
blog.example.com → /var/www/blog
```

같은 IP와 포트를 사용하더라도 요청의 Host 이름을 기준으로 사이트를 구분할 수 있다.

### 주요 지시어

| 지시어 | 역할 |
|---|---|
| VirtualHost | 개별 사이트의 설정 블록 |
| ServerName | 사이트의 대표 호스트 이름 |
| ServerAlias | 추가로 허용할 호스트 이름 |
| DocumentRoot | 웹 파일을 제공할 기준 경로 |
| Directory | 디렉터리 접근 및 동작 정책 |
| ErrorLog | 오류 로그 저장 위치 |
| CustomLog | HTTP 접근 로그 저장 위치 |

주의: ServerName을 설정해도 DNS가 자동으로 등록되는 것은 아니다.

## 4. VirtualHost 구축 순서

### 전체 흐름

```text
① 웹 디렉터리 및 HTML 파일 생성
              ↓
② VirtualHost 설정 파일 작성
              ↓
③ a2ensite로 사이트 활성화
              ↓
④ configtest 및 VirtualHost 확인
              ↓
⑤ Apache 설정 reload
              ↓
⑥ curl로 실제 HTTP 응답 검증
```

### ① 웹 디렉터리 및 파일 생성

```bash
sudo mkdir -p /var/www/web01/public

sudo chown -R root:root /var/www/web01

sudo chmod 755 /var/www/web01
sudo chmod 755 /var/www/web01/public

echo '<h1>WEB01 Apache VirtualHost OK</h1>' | \
sudo tee /var/www/web01/public/index.html
```

명령어 설명:

- mkdir -p: 상위 디렉터리까지 생성
- chown -R: 하위 파일과 디렉터리의 소유권을 재귀적으로 변경
- chmod 755: 소유자 rwx, 그룹 및 기타 사용자 r-x
- tee: 입력받은 내용을 파일에 기록

### ② VirtualHost 설정 파일 작성

```bash
sudo nano /etc/apache2/sites-available/web01.conf
```

설정 내용:

```apache
<VirtualHost *:80>
    ServerName web01.test
    DocumentRoot /var/www/web01/public

    <Directory /var/www/web01/public>
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/web01-error.log
    CustomLog ${APACHE_LOG_DIR}/web01-access.log combined
</VirtualHost>
```

#### 설정 분석

- `<VirtualHost *:80>`: 80번 포트로 들어온 요청에 적용할 사이트 설정
- `ServerName`: 요청 호스트 이름 지정
- `DocumentRoot`: 웹 파일 기준 디렉터리
- `Options -Indexes`: 디렉터리 목록 표시 비활성화
- `Options +FollowSymLinks`: 심볼릭 링크 사용 허용
- `AllowOverride None`: .htaccess를 통한 설정 재정의 비허용
- `Require all granted`: Apache 접근 제어에서 요청 허용
- `ErrorLog`: 오류 로그 기록
- `CustomLog`: 접근 로그 기록
- `combined`: 일반적인 결합형 접근 로그 포맷

주의: Require all granted는 Linux 파일 권한을 변경하지 않는다.

### ③ 사이트 활성화

```bash
sudo a2ensite web01.conf
```

활성화 여부 확인:

```bash
ls -l /etc/apache2/sites-enabled/
```

a2ensite는 sites-enabled에 설정 파일을 가리키는 심볼릭 링크를 생성한다.

반대로 비활성화할 때는 다음 명령어를 사용한다.

```bash
sudo a2dissite web01.conf
```

비활성화해도 원본 설정 파일은 삭제되지 않는다.

### ④ 설정 문법 및 VirtualHost 확인

```bash
sudo apache2ctl configtest
```

정상 결과:

```text
Syntax OK
```

VirtualHost 구성 확인:

```bash
sudo apache2ctl -S
```

- configtest: Apache 설정 문법 검사
- apache2ctl -S: Apache가 인식하는 VirtualHost 및 기본 사이트 확인

### ⑤ Apache 설정 적용

```bash
sudo systemctl reload apache2
```

reload는 가능한 경우 기존 서비스를 완전히 중단하지 않고 설정을 다시 적용한다.

설정 수정 후에는 다음 순서로 진행한다.

```text
설정 수정 → configtest → reload → 실제 응답 확인
```

### ⑥ HTTP 응답 검증

Host 헤더를 지정해 요청:

```bash
curl -i -H "Host: web01.test" http://127.0.0.1/
```

또는 DNS를 수정하지 않고 IP를 지정하여 확인:

```bash
curl -i --resolve web01.test:80:192.168.111.141 \
http://web01.test/
```

정상 응답 예시:

```text
HTTP/1.1 200 OK

<h1>WEB01 Apache VirtualHost OK</h1>
```

옵션 설명:

- curl -i: 응답 헤더와 본문 출력
- curl -H: 요청 헤더 지정
- curl --resolve: 특정 호스트와 포트에 연결할 IP 지정

## 5. 기본 사이트 비활성화

새 VirtualHost가 정상 동작하는지 확인한 뒤,
필요하다면 Apache 기본 사이트를 비활성화한다.

```bash
sudo a2dissite 000-default.conf

sudo apache2ctl configtest

sudo systemctl reload apache2
```

이후:

```bash
curl -i http://192.168.111.141/
```

새 웹사이트가 기본 사이트로 선택되는지 확인한다.

주의: 실제 운영 중에는 다른 사이트에 영향이 없는지 먼저 확인한다.

## 6. 장애 대응

### ① HTTP 403 Forbidden

가능한 원인:

- Apache Directory 접근 정책 오류
- Linux 파일 및 디렉터리 권한 문제
- 기본 index 파일 부재 및 디렉터리 목록 차단

확인 명령어:

```bash
ls -ld /var/www/web01
ls -ld /var/www/web01/public
ls -l /var/www/web01/public/index.html

sudo tail -n 30 /var/log/apache2/web01-error.log
```

파일 권한이 문제인지 확인하고 필요한 최소 권한만 설정한다.

무조건 chmod 777을 사용하지 않는다.

### ② HTTP 404 Not Found

가능한 원인:

- 요청한 파일이 존재하지 않음
- DocumentRoot 경로 오류
- 다른 VirtualHost가 선택됨

점검:

```bash
ls -l /var/www/web01/public/
sudo apache2ctl -S
```

### ③ 새로운 VirtualHost 대신 기본 페이지가 표시됨

가능한 원인:

- 사이트가 활성화되지 않음
- ServerName과 요청 Host 이름 불일치
- 기본 VirtualHost가 선택됨
- 설정 reload 누락

점검:

```bash
ls -l /etc/apache2/sites-enabled/

sudo apache2ctl -S

curl -i -H "Host: web01.test" http://127.0.0.1/
```

### ④ Apache 설정 오류

```bash
sudo apache2ctl configtest

sudo systemctl status apache2

sudo journalctl -u apache2 -n 50 --no-pager
```

설정 오류가 있다면 재시작하기 전에 수정한다.

## 9. 최종 핵심 정리

1. VirtualHost는 하나의 Apache에서 여러 사이트를 구분하여 운영하는 기능이다.
2. ServerName은 사이트의 호스트 이름을 지정한다.
3. DocumentRoot는 웹 콘텐츠를 제공할 기준 디렉터리이다.
4. sites-available에 설정 파일을 만들고 a2ensite로 활성화한다.
5. configtest로 문법을 검사하고 apache2ctl -S로 사이트 구성을 확인한다.
6. reload 후 curl로 실제 HTTP 응답을 검증한다.
7. 장애 발생 시 사이트 활성화 여부, Host 이름, 파일 경로, 권한, 로그를 확인한다.

### 반드시 기억할 순서

**설정 작성 → 활성화 → 문법 검사 → VirtualHost 확인 → reload → HTTP 검증**
