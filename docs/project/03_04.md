
# A과정 3장 4교시 — Apache Reverse Proxy 및 WAS 연동

## 1. 실습 환경

| 서버 | IP | 역할 | 포트 |
|---|---|---|---|
| WEB01 | 192.168.111.141 | Apache | 80 |
| WAS01 | 192.168.111.142 | Spring Boot / 임시 HTTP 서버 | 8080 |

### 요청 흐름

```text
사용자
  ↓ HTTP :80
Apache WEB01
  ↓ Reverse Proxy
WAS01 :8080
  ↓ HTTP 응답
Apache WEB01
  ↓
사용자
```

이번 실습에서는 Apache의 `/app/` 경로만 WAS에 전달한다.

- `/` → Apache가 정적 페이지 제공
- `/app/` → WAS01의 `/`로 요청 전달
- `/app/health` → WAS01의 `/health`로 요청 전달

---

## 2. Reverse Proxy란?

클라이언트의 HTTP 요청을 대신 받아 백엔드 서버에 전달하는 기능이다.

### 사용하는 이유

- WEB과 WAS의 역할 분리
- Apache를 통해 WAS 요청 전달
- 정적 콘텐츠와 애플리케이션 요청 구분
- 여러 WAS로의 요청 분산 구조 확장 가능

주의: Reverse Proxy를 설정했다고 자동으로 WAS가 이중화되거나 외부 접근이 차단되는 것은 아니다.

---

## 3. Apache Proxy 모듈

필요한 모듈:

| 모듈 | 역할 |
|---|---|
| mod_proxy | 프록시 핵심 기능 |
| mod_proxy_http | HTTP 백엔드 요청 처리 |

### 모듈 활성화

```bash
# WEB01
sudo a2enmod proxy proxy_http

# 활성화된 모듈 확인
apache2ctl -M | grep proxy
```

예상 출력:

```text
proxy_module (shared)
proxy_http_module (shared)
```

- `a2enmod`: Apache 모듈 활성화
- `apache2ctl -M`: 로드된 모듈 목록
- `grep`: 문자열 필터링

## 4. WAS01 HTTP 서버 준비

실습 시 Spring Boot가 없다면 Python 임시 서버로 프록시를 검증한다.

### WAS01에서 실행

```bash
mkdir -p ~/proxy-test

echo "Response from WAS01" > ~/proxy-test/index.html

python3 -m http.server 8080 \
  --bind 0.0.0.0 \
  --directory ~/proxy-test
```

### 주요 옵션

- `-m http.server`: Python HTTP 서버 실행
- `8080`: 수신 포트
- `--bind 0.0.0.0`: 모든 IPv4 인터페이스에서 수신
- `--directory`: 웹 파일을 제공할 디렉터리

Python HTTP 서버는 실습용으로만 사용한다.

### WAS01 정상 동작 확인

다른 터미널에서:

```bash
curl -i http://127.0.0.1:8080/
```

예상 응답 본문:

```text
Response from WAS01
```

## 5. WEB01 → WAS01 통신 확인

Apache 설정 전에 직접 통신이 가능한지 확인한다.

### WEB01에서 실행

```bash
# TCP 8080 연결 확인
nc -vz -w 3 192.168.111.142 8080

# HTTP 응답 확인
curl -i http://192.168.111.142:8080/
```

### nc 옵션

- `-v`: 상세 정보 출력
- `-z`: TCP 포트 연결 검사
- `-w 3`: 연결 대기 시간 3초

중요:
`nc`는 목적지 IP와 포트를 공백으로 구분한다.

```bash
# 올바른 형식
nc -vz 192.168.111.142 8080
```

### WAS01 방화벽 확인

```bash
# WAS01
sudo ufw status verbose
```

필요한 경우 WEB01에서 오는 8080 요청만 허용:

```bash
sudo ufw allow from 192.168.111.141 \
  to any port 8080 proto tcp
```

## 6. Apache Reverse Proxy 설정

### 설정 파일 백업

```bash
# WEB01
sudo cp /etc/apache2/sites-available/web01.conf \
  /etc/apache2/sites-available/web01.conf.bak
```

### 설정 파일 편집

```bash
sudo nano /etc/apache2/sites-available/web01.conf
```

### VirtualHost 설정

```apache
<VirtualHost *:80>
    ServerName web01.test

    DocumentRoot /var/www/web01/public

    <Directory /var/www/web01/public>
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted
    </Directory>

    ProxyRequests Off

    ProxyPass "/app/" "http://192.168.111.142:8080/"
    ProxyPassReverse "/app/" "http://192.168.111.142:8080/"

    ErrorLog ${APACHE_LOG_DIR}/web01-error.log
    CustomLog ${APACHE_LOG_DIR}/web01-access.log combined
</VirtualHost>
```

### 중요한 지시어

| 지시어 | 역할 |
|---|---|
| ProxyRequests Off | Forward Proxy 기능 비활성화 |
| ProxyPass | 요청을 WAS로 전달 |
| ProxyPassReverse | WAS의 리다이렉션 관련 응답 헤더 URL 보정 |
| DocumentRoot | 정적 파일 기준 디렉터리 |
| ErrorLog | Apache 오류 로그 |
| CustomLog | HTTP 접근 로그 |

### ProxyPass와 ProxyPassReverse 차이

**ProxyPass**
- 클라이언트 → WAS 요청 전달

**ProxyPassReverse**
- WAS → 클라이언트 응답 중 리다이렉션 관련 헤더 URL 보정

ProxyPassReverse는 HTML 본문이나 쿠키를 모두 자동 수정하지 않는다.

---

## 7. ProxyPass 경로 변환 원리

설정:

```apache
ProxyPass "/app/" "http://192.168.111.142:8080/"
```

Apache는 `/app/` 부분을 백엔드 URL의 `/`로 대응시킨다.

| 사용자가 요청한 경로 | WAS가 받는 경로 |
|---|---|
| /app/ | / |
| /app/users | /users |
| /app/health | /health |
| /app/login | /login |

예시:

```text
사용자: http://web01.test/app/users

Apache ProxyPass

WAS01: http://192.168.111.142:8080/users
```

**중요: `/app/users`가 WAS의 `/app/users`로 그대로 전달되는 것이 아니다.**

실제 Spring Boot 애플리케이션이 `/app/` 경로를 기준으로 동작하도록 설계되지 않았다면, 쿠키·리다이렉션·절대 URL 등에 추가 설정이 필요할 수 있다.

## 8. Apache 설정 적용

```bash
# 사이트 활성화 상태 확인
ls -l /etc/apache2/sites-enabled/

# 필요하다면 활성화
sudo a2ensite web01.conf

# 문법 검사
sudo apache2ctl configtest

# VirtualHost 확인
sudo apache2ctl -S

# 설정 재적용
sudo systemctl reload apache2
```

### 핵심 순서

```text
설정 수정
   ↓
configtest
   ↓
VirtualHost 확인
   ↓
reload
   ↓
HTTP 요청 검증
   ↓
로그 확인
```

`Syntax OK`는 문법이 정상이라는 의미이며, WAS 연결까지 보장하지는 않는다.

## 9. Reverse Proxy 정상 동작 검증

### ① Apache 정적 페이지

```bash
# WEB01
curl -i -H "Host: web01.test" http://127.0.0.1/
```

예상 본문:

```html
<h1>WEB01 Apache VirtualHost OK</h1>
```

### ② Apache를 통한 WAS 응답

```bash
curl -i -H "Host: web01.test" http://127.0.0.1/app/
```

예상 본문:

```text
Response from WAS01
```

### ③ Windows에서 접속

```powershell
curl.exe -i -H "Host: web01.test" http://192.168.111.141/app/
```

### 정상 동작 판단

- `/` 요청 → Apache 정적 페이지
- `/app/` 요청 → WAS01 응답
- Apache와 WAS 로그에서 요청 확인

이 결과를 통해 Apache가 요청 경로에 따라 직접 응답하거나 백엔드에 전달하는 것을 검증할 수 있다.

## 10. 로그 확인

### WEB01 Apache Access Log

```bash
sudo tail -f /var/log/apache2/web01-access.log
```

클라이언트의 `/app/` 요청이 기록되는지 확인한다.

### WEB01 Apache Error Log

```bash
sudo tail -n 50 /var/log/apache2/web01-error.log
```

백엔드 연결 실패나 Proxy 오류 확인에 사용한다.

### WAS01

Python 임시 HTTP 서버 터미널에서 실제 요청을 받았는지 확인한다.

예시:

```text
192.168.111.141 - - "GET / HTTP/1.1" 200 -
```

이것은 WEB01에서 WAS01로 요청이 전달된 사실을 확인하는 데 도움이 된다.

## 11. Reverse Proxy 장애 대응

### 상황: Apache는 실행 중이지만 /app/ 요청에 503 발생

#### ① WAS01의 8080 수신 확인

WAS01에서 실행:

```bash
sudo ss -lntp '( sport = :8080 )'
```

WAS01의 HTTP 서버가 8080을 수신하는지 확인한다.

#### ② WEB01에서 WAS01 연결 확인

WEB01에서 실행:

```bash
nc -vz -w 3 192.168.111.142 8080
```

WEB에서 WAS로 TCP 연결할 수 있는지 확인한다.

#### ③ WAS01 방화벽 확인

WAS01에서 실행:

```bash
sudo ufw status verbose
```

WEB01의 접근이 허용되는지 확인한다.

#### ④ 실제 HTTP 응답 확인

WEB01에서 실행:

```bash
curl -i http://192.168.111.142:8080/
```

TCP 연결뿐 아니라 HTTP 응답이 정상인지 확인한다.

#### ⑤ Apache Error Log 확인

WEB01에서 실행:

```bash
sudo tail -n 50 /var/log/apache2/web01-error.log
```

Apache가 백엔드에 연결하거나 응답을 처리하는 과정에서 기록한 오류를 확인한다.

### 502와 503

- 502 Bad Gateway: 유효하지 않은 업스트림 응답 등
- 503 Service Unavailable: 백엔드 사용 불가 등

실제 원인은 Apache Error Log 및 WAS 상태를 함께 확인해야 한다.

### 장애 분석 핵심

```text
Apache 실행 상태 확인
        ↓
WAS01의 8080 LISTEN 확인
        ↓
WEB01 → WAS01 TCP 연결 확인
        ↓
HTTP 직접 요청 확인
        ↓
UFW 및 네트워크 확인
        ↓
Apache Error Log 확인
        ↓
설정 또는 서비스 복구
        ↓
Apache 경유 HTTP 재검증
```

## 12. 확인문제 및 정답

### 1번
Apache HTTP Reverse Proxy에 필요한 모듈은?

정답: ② mod_proxy, mod_proxy_http

### 2번
ProxyPass의 역할은?

정답: ③ 클라이언트 요청을 백엔드로 전달

### 3번
ProxyPassReverse의 역할은?

정답: ① 백엔드의 특정 리다이렉션 응답 헤더 URL 보정

### 4번
WEB01에서 WAS01의 TCP 8080 연결을 확인하는 명령어는?

정답: ④ nc -vz 192.168.111.142 8080

### 5번
/app/users 요청이 WAS에 전달되는 경로는?

정답: ② /users

해설:
ProxyPass 설정에 따라 `/app/`이 백엔드의 `/`로 대응된다.

### 6번 서술형
Apache는 실행 중이지만 /app/에 503 오류가 발생한다.
어떤 명령어를 사용해 WEB→WAS 연결 문제를 점검하는가?

모범 답안:

```bash
# WAS01: 포트 수신 상태
sudo ss -lntp '( sport = :8080 )'

# WEB01: WAS TCP 연결
nc -vz -w 3 192.168.111.142 8080

# WAS01: 방화벽 확인
sudo ufw status verbose

# WEB01: HTTP 응답 확인
curl -i http://192.168.111.142:8080/

# WEB01: 프록시 오류 로그 확인
sudo tail -n 50 /var/log/apache2/web01-error.log
```

### 채점 결과

- 객관식: 4/5 정답 (80점)
- 오답: 5번 ProxyPass 경로 변환
- 서술형: 점검 방향 적절, 명령어 문법 보완 필요

---

## 13. 최종 핵심 정리

1. Apache는 Reverse Proxy를 이용해 WAS로 요청을 전달한다.
2. mod_proxy와 mod_proxy_http 모듈이 필요하다.
3. ProxyPass는 요청 전달, ProxyPassReverse는 리다이렉션 관련 응답 헤더 보정이다.
4. `/app/users` 요청은 이번 설정에서 WAS의 `/users`로 전달된다.
5. 프록시 설정 전에 WEB→WAS 직접 연결을 확인한다.
6. configtest → reload → curl → 로그 확인 순서로 검증한다.
7. 503 발생 시 WAS의 수신 포트, WEB→WAS 연결, 방화벽, HTTP 응답, Apache 로그를 확인한다.

### 반드시 기억할 구축 순서

**WAS 준비 → 직접 연결 확인 → Proxy 모듈 활성화 → ProxyPass 설정 → configtest → reload → 프록시 요청 검증 → 로그 확인**
