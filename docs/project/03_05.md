
# A과정 3장 5교시 — Apache 로그 분석 및 운영 관리

## 1. 학습 목표

- Access Log와 Error Log의 차이 이해
- HTTP 상태 코드 분석
- tail, grep, awk를 사용한 로그 확인
- journalctl로 Apache 서비스 오류 확인
- logrotate를 통한 로그 관리
- 로그를 활용한 장애 원인 분석

### 실습 환경

- WEB01: 192.168.111.141 (Apache)
- WAS01: 192.168.111.142 (Spring Boot / HTTP 서버)
- Apache 포트: 80
- WAS 포트: 8080

---

## 2. Apache 로그 종류

| 로그 | 역할 | 확인 대상 |
|---|---|---|
| Access Log | HTTP 요청 및 응답 기록 | IP, URL, 상태 코드, 요청 시간 |
| Error Log | 서버 및 요청 처리 오류 기록 | 프록시 오류, 연결 실패, 권한 문제 |
| systemd Journal | Apache 서비스 관련 기록 | 시작, 종료, 실행 실패 |

### 실습 환경의 로그 경로

```text
/var/log/apache2/web01-access.log
/var/log/apache2/web01-error.log
```

위 경로는 web01.conf에서 별도로 지정한 경로다.

Ubuntu Apache의 기본 로그는 일반적으로 다음 경로를 사용한다.

```text
/var/log/apache2/access.log
/var/log/apache2/error.log
```

### 핵심 차이

- Access Log: 어떤 요청에 어떤 응답이 발생했는가?
- Error Log: 요청 처리 중 어떤 오류가 기록되었는가?

주의: Error Log에 모든 HTTP 오류가 반드시 기록되는 것은 아니다.

## 3. Access Log 분석

### 로그 예시

```text
192.168.111.100 - - [23/Oct/2026:12:30:15 +0900] "GET /app/health HTTP/1.1" 503 299 "-" "curl/8.5.0"
```

| 항목 | 의미 |
|---|---|
| 192.168.111.100 | 클라이언트 IP |
| 23/Oct/2026 | 요청 날짜 |
| 12:30:15 | 요청 시간 |
| GET | HTTP 메서드 |
| /app/health | 요청 URL 경로 |
| HTTP/1.1 | HTTP 버전 |
| 503 | HTTP 응답 상태 코드 |
| 299 | 응답 본문 크기(바이트) |
| curl/8.5.0 | User-Agent |

### 주요 HTTP 상태 코드

| 코드 | 의미 |
|---|---|
| 200 | 요청 성공 |
| 301 / 302 | 리다이렉션 |
| 403 | 접근 거부 |
| 404 | 요청 자원 없음 |
| 500 | 서버 내부 오류 |
| 502 | Bad Gateway |
| 503 | Service Unavailable |

중요: HTTP 503이 발생했다고 무조건 WAS가 종료되었다고 판단하면 안 된다.

## 4. 필수 로그 확인 명령어

### ① 최근 로그 확인

```bash
sudo tail -n 50 /var/log/apache2/web01-access.log
```

- tail: 파일 마지막 내용 출력
- -n 50: 마지막 50줄 출력

### ② 실시간 로그 확인

```bash
sudo tail -f /var/log/apache2/web01-access.log
```

- -f: 추가되는 로그를 계속 출력
- Ctrl+C: 종료

로그 회전으로 파일이 교체되는 상황에서는 `tail -F`도 유용하다.

### ③ 오류 로그 확인

```bash
sudo tail -n 50 /var/log/apache2/web01-error.log
```

### ④ 특정 요청 검색

```bash
sudo grep '/app/health' /var/log/apache2/web01-access.log
```

- grep: 지정한 문자열이 포함된 줄 검색

### ⑤ HTTP 상태 코드 추출

```bash
sudo awk '{print $9}' /var/log/apache2/web01-access.log
```

- awk: 필드 단위 문자열 처리
- $9: 일반적인 combined 형식에서 HTTP 상태 코드 위치

단, 로그 형식이 변경되면 필드 위치가 달라질 수 있다.

### ⑥ HTTP 상태 코드별 개수 집계

```bash
sudo awk '{print $9}' /var/log/apache2/web01-access.log \
  | sort \
  | uniq -c
```

- sort: 정렬
- uniq -c: 같은 값의 개수 집계

### ⑦ Apache 서비스 로그 확인

```bash
sudo journalctl -u apache2 -n 30 --no-pager
```

- -u apache2: apache2 서비스 기록
- -n 30: 최근 30줄
- --no-pager: 페이지 뷰어 없이 출력

## 5. 로그 기반 장애 대응

### 상황

사용자가 다음 주소에 접속했을 때 HTTP 503 발생

```text
http://web01.test/app/health
```

### ① Access Log 확인 — WEB01

```bash
sudo tail -n 50 /var/log/apache2/web01-access.log
```

확인할 내용:

- /app/health 요청이 들어왔는가?
- HTTP 503이 기록되었는가?
- 어느 시간에 발생했는가?

### ② Error Log 확인 — WEB01

```bash
sudo tail -n 50 /var/log/apache2/web01-error.log
```

확인할 내용:

- WAS 연결 거부 여부
- WAS 응답 타임아웃 여부
- Apache Reverse Proxy 오류 메시지

### ③ WAS 포트 수신 확인 — WAS01

```bash
sudo ss -lntp '( sport = :8080 )'
```

WAS01이 TCP 8080을 수신하는지 확인한다.

### ④ WEB → WAS 연결 확인 — WEB01

```bash
nc -vz -w 3 192.168.111.142 8080
```

WEB01에서 WAS01의 TCP 8080 포트에 연결되는지 확인한다.

### ⑤ 직접 HTTP 요청 — WEB01

```bash
curl -i http://192.168.111.142:8080/health
```

WAS가 실제로 HTTP 응답을 반환하는지 확인한다.

### ⑥ Apache 경유 HTTP 검증 — WEB01

```bash
curl -i -H "Host: web01.test" \
  http://127.0.0.1/app/health
```

복구 후 Apache를 경유해 정상 응답이 나오는지 확인한다.

### 핵심 장애 대응 순서

```text
HTTP 503 발생
      ↓
Access Log 확인 (어떤 요청에서 실패?)
      ↓
Error Log 확인 (어떤 오류가 기록됨?)
      ↓
WAS01 8080 LISTEN 확인
      ↓
WEB01 → WAS01 TCP 연결 확인
      ↓
WAS 직접 HTTP 응답 확인
      ↓
원인 해결
      ↓
Apache 경유 HTTP 재검증
```

## 6. 로그 파일 용량 관리

로그가 계속 쌓이면 디스크 용량이 부족해질 수 있다.

### 로그 크기 확인

```bash
sudo ls -lh /var/log/apache2/
```

### 로그 디렉터리 사용량 확인

```bash
sudo du -sh /var/log/apache2/
```

- du: 디렉터리 및 파일 사용량
- -s: 합계 출력
- -h: 사람이 읽기 쉬운 단위 출력

### 디스크 사용량 확인

```bash
df -h
```

- df: 파일시스템 사용량 확인

## 7. logrotate란?

로그 파일을 주기적으로 회전·압축·보관·삭제하여 관리하는 도구이다.

### 로그 관리 예시

```text
web01-access.log        ← 현재 로그
web01-access.log.1      ← 이전 로그
web01-access.log.2.gz   ← 압축된 이전 로그
```

### Apache logrotate 설정 확인

```bash
sudo cat /etc/logrotate.d/apache2
```

### 주요 설정

| 설정 | 의미 |
|---|---|
| daily | 일 단위 회전 조건 |
| weekly | 주 단위 회전 조건 |
| rotate 14 | 회전 로그 최대 14개 보관 |
| compress | 이전 로그 압축 |
| delaycompress | 최근 회전 로그의 압축 지연 |
| missingok | 파일이 없어도 오류로 처리하지 않음 |
| notifempty | 빈 로그는 회전하지 않음 |
| postrotate | 로그 회전 후 명령 실행 |

실제 적용된 값은 시스템 설정 파일을 직접 확인해야 한다.

### 설정 검증

```bash
sudo logrotate -d /etc/logrotate.conf
```

- -d: 실제 회전 없이 설정과 동작 판단을 확인

주의: 운영 중 로그를 임의로 삭제하거나 강제 회전하기 전에 적용 범위와 후처리 설정을 확인한다.

## 8. 확인문제 및 정답

### 1번
Apache Access Log의 주요 목적은?

정답: ② HTTP 요청과 응답 상태 기록

### 2번
"GET /app/health HTTP/1.1" 503 120 에서 상태 코드는?

정답: ③ 503

### 3번
새 로그가 기록되는 것을 실시간 확인하는 명령어는?

정답: ① tail -f

### 4번
Apache 서비스 시작·종료 기록 확인 명령어는?

정답: ④ journalctl -u apache2

### 5번
logrotate의 주요 역할은?

정답: ② 로그 회전·보관·압축·정리

### 6번 서술형
/app/health에서 503이 발생하면 Access Log와 Error Log에서 무엇을 확인하는가?

모범 답안:

Access Log를 통해 /app/health 요청이 들어왔는지와 HTTP 503이 발생했는지 확인한다.

Error Log를 통해 WAS 연결 거부, 타임아웃, Proxy 관련 오류가 있는지 확인한다.

명령어:

```bash
sudo tail -n 50 /var/log/apache2/web01-access.log
sudo tail -n 50 /var/log/apache2/web01-error.log
```

### 보충문제

1. Access Log의 503만으로 WAS 종료를 확정할 수 있는가?
   - 정답: 아니요. 추가 원인 분석이 필요하다.

2. Error Log에서 WAS01:8080 연결 거부가 발생하면?
   - 정답: WAS01의 8080 LISTEN 상태와 WEB→WAS 연결 확인

## 9. 최종 핵심 정리

1. Access Log는 HTTP 요청과 응답 결과를 기록한다.
2. Error Log는 Apache 오류와 진단 정보를 기록한다.
3. tail -f는 실시간 로그, grep은 문자열 검색에 사용한다.
4. awk와 sort, uniq를 조합하면 상태 코드별 요청 수를 집계할 수 있다.
5. journalctl은 Apache 서비스 시작·종료·실패 관련 기록을 확인한다.
6. logrotate는 로그 파일의 회전·압축·보관을 관리한다.
7. 장애 발생 시 로그에서 현상을 확인하고, 서버 상태 및 네트워크 검사로 원인을 좁혀야 한다.

### 반드시 기억할 문장

**Access Log로 현상을 확인하고, Error Log로 원인 단서를 찾고, 명령어로 검증한 후 복구한다.**
