
# A과정 3장 6교시 — Apache 보안 및 MPM 성능 관리

## 1. Apache 실행 계정

Apache는 일반적으로 부모 프로세스가 root, 요청을 처리하는 작업 프로세스가 www-data 계정으로 실행된다.

이유: 웹 요청 처리 프로세스의 권한을 제한하여 보안 위험을 줄이기 위해서다.

### 실행 계정 확인

```bash
ps -eo user,group,pid,ppid,comm | grep '[a]pache2'
```

- user/group: 실행 사용자와 그룹
- pid: 프로세스 ID
- ppid: 부모 프로세스 ID

---

## 2. Linux 파일 권한과 Apache 접근 정책

Apache가 웹 파일을 제공하려면 다음 두 조건이 필요하다.

1. Linux 파일시스템에서 읽기 및 경로 탐색이 가능해야 한다.
2. Apache 설정에서 접근을 허용해야 한다.

### 권한 확인

```bash
ls -ld /var/www/web01/public
ls -l /var/www/web01/public/index.html

namei -l /var/www/web01/public/index.html
```

### 일반적인 정적 파일 권한

```bash
sudo chmod 755 /var/www/web01/public
sudo chmod 644 /var/www/web01/public/index.html
```

- 755: 소유자 rwx, 그룹·기타 사용자 r-x
- 644: 소유자 rw-, 그룹·기타 사용자 r--

### Apache 계정의 파일 읽기 확인

```bash
sudo -u www-data test -r \
  /var/www/web01/public/index.html \
  && echo "Readable OK"
```

### Apache 접근 설정

```apache
<Directory /var/www/web01/public>
    Options -Indexes +FollowSymLinks
    AllowOverride None
    Require all granted
</Directory>
```

- -Indexes: 디렉터리 목록 표시 차단
- +FollowSymLinks: 심볼릭 링크 사용 허용
- AllowOverride None: .htaccess 재정의 비허용
- Require all granted: Apache 차원의 접근 허용

핵심: Linux 권한과 Apache 접근 정책은 서로 다르다.

## 3. Apache 기본 보안 설정

설정 파일:

/etc/apache2/conf-available/security.conf

### 주요 설정

```apache
ServerTokens Prod
ServerSignature Off
TraceEnable Off
```

| 설정 | 역할 |
|---|---|
| ServerTokens Prod | 응답 헤더의 Apache 버전 정보 노출 축소 |
| ServerSignature Off | 오류 페이지 등의 서버 서명 정보 비활성화 |
| TraceEnable Off | HTTP TRACE 메서드 비활성화 |

주의: 버전 정보 노출을 줄여도 실제 취약점이 해결되는 것은 아니다.

### 설정 검증

```bash
sudo apache2ctl configtest
sudo systemctl reload apache2

# 응답 헤더 확인
curl -I -H "Host: web01.test" http://127.0.0.1/

# TRACE 비활성화 확인
curl -i -X TRACE \
  -H "Host: web01.test" http://127.0.0.1/
```

TRACE 요청은 일반적으로 405 응답을 기대한다.

## 4. MPM이란?

MPM(Multi-Processing Module)은 Apache가 여러 클라이언트의 요청을 처리하는 프로세스·스레드 구조를 결정하는 모듈이다.

| MPM | 특징 |
|---|---|
| prefork | 프로세스 중심, 각 자식 프로세스가 단일 요청 처리 스레드 사용 |
| worker | 여러 프로세스와 스레드를 사용 |
| event | worker 구조를 기반으로 Keep-Alive 등의 유휴 연결 대기 처리를 개선 |

### MPM 확인

```bash
apache2ctl -M | grep mpm
```

출력 예시:

```text
mpm_event_module (shared)
```

Apache는 한 번에 하나의 MPM을 사용한다.

## 5. MPM 주요 성능 설정

event MPM 설정 파일:

/etc/apache2/mods-available/mpm_event.conf

설정 예시:

```apache
StartServers             2
MinSpareThreads         25
MaxSpareThreads         75
ThreadsPerChild         25
MaxRequestWorkers      150
MaxConnectionsPerChild   0
```

| 설정 | 의미 |
|---|---|
| StartServers | 시작 시 자식 프로세스 수 |
| MinSpareThreads | 최소 유휴 스레드 수 |
| MaxSpareThreads | 최대 유휴 스레드 수 |
| ThreadsPerChild | 프로세스당 작업 스레드 수 |
| MaxRequestWorkers | 동시 작업 요청 처리 상한 |
| MaxConnectionsPerChild | 자식 프로세스의 연결 처리 한도 |

예시:

ThreadsPerChild 25 × 프로세스 6개 = 작업 스레드 150개

주의:
MaxRequestWorkers를 무조건 늘리면 메모리 및 CPU 사용량이 증가할 수 있다.

## 6. Apache 성능 확인 명령어

```bash
# CPU 처리 단위 수
nproc

# 메모리 사용량
free -h

# Apache 프로세스와 자원 사용량
ps -C apache2 -o pid,ppid,%cpu,rss,cmd

# MPM 관련 경고 검색
sudo grep -Ei 'MaxRequestWorkers|server reached' \
  /var/log/apache2/error.log

# Apache 서비스 로그
sudo journalctl -u apache2 -n 30 --no-pager
```

성능 저하 시 Apache뿐 아니라 WAS와 DB의 처리 지연도 확인해야 한다.

## 7. 장애 대응

### HTTP 403 Forbidden

확인할 내용:
- Linux 파일 및 디렉터리 권한
- Apache Directory 접근 정책
- 적용된 VirtualHost 설정
- Apache Error Log

```bash
sudo apache2ctl -S
namei -l /var/www/web01/public/index.html
sudo tail -n 30 /var/log/apache2/web01-error.log
```

403이라고 무조건 chmod 777을 사용하지 않는다.

### Apache 응답 지연

확인할 내용:
- 활성 MPM 종류
- CPU 및 메모리 사용량
- MaxRequestWorkers 관련 경고
- WAS 응답 지연 여부

MPM 설정값을 변경하기 전에 병목 구간을 먼저 확인한다.

---

## 8. 반드시 기억할 핵심

1. Apache 작업 프로세스는 일반적으로 www-data로 실행된다.
2. Linux 파일 권한과 Apache 접근 정책을 모두 확인해야 한다.
3. ServerTokens, ServerSignature, TraceEnable은 기본 보안 설정에 사용된다.
4. MPM은 Apache의 동시 요청 처리 방식을 결정한다.
5. event MPM은 유휴 연결 대기 처리를 효율적으로 관리한다.
6. MaxRequestWorkers를 무조건 증가시키면 안 된다.
7. 보안·성능 설정 변경 후 configtest, reload, HTTP 응답을 검증해야 한다.

### 핵심 문장

**보안은 최소 권한을 적용하고, 성능은 병목을 확인한 후 조정한다.**
