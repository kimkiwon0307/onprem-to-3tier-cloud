
# A과정 3장 7교시 — Apache 종합 장애 대응

## 1. 학습 목표

Apache 장애 발생 시 다음 순서로 문제를 해결한다.

**증상 확인 → 문제 구간 파악 → 로그 분석 → 원인 해결 → 정상 동작 검증**

### 실습 환경

- WEB01: 192.168.111.141 (Apache, TCP 80)
- WAS01: 192.168.111.142 (HTTP 서버, TCP 8080)
- `/` → Apache 정적 페이지
- `/app/` → Reverse Proxy를 통해 WAS01로 전달

---

## 2. Apache 기본 장애 점검

WEB01에서 실행한다.

```bash
# 서비스 상태
sudo systemctl status apache2

# TCP 80 LISTEN 확인
sudo ss -lntp '( sport = :80 )'

# 설정 문법 확인
sudo apache2ctl configtest

# VirtualHost 확인
sudo apache2ctl -S

# 서비스 오류 로그
sudo journalctl -u apache2 -n 50 --no-pager
```

### 명령어 역할

| 명령어 | 확인 목적 |
|---|---|
| systemctl status | Apache 실행 여부 |
| ss -lntp | 포트 수신 및 프로세스 확인 |
| apache2ctl configtest | 설정 문법 오류 확인 |
| apache2ctl -S | VirtualHost 설정 확인 |
| journalctl | 서비스 시작·실패 기록 확인 |

Apache가 실행되지 않는다면 설정 오류, 포트 충돌, 모듈 오류 등을 확인한다.

---

## 3. HTTP 상태 코드별 장애 대응

| 상태 코드 | 의미 | 주요 점검 대상 |
|---|---|---|
| 403 | Forbidden | 파일 권한, Directory 접근 정책 |
| 404 | Not Found | 파일 경로, DocumentRoot, URL |
| 502 | Bad Gateway | WAS 응답, Reverse Proxy |
| 503 | Service Unavailable | WAS 상태, 연결 실패, 프록시 설정 |

**상태 코드만 보고 장애 원인을 확정하지 않는다.**

### ① HTTP 403 Forbidden

```bash
# 파일과 상위 디렉터리 권한 확인
namei -l /var/www/web01/public/index.html

# Apache 설정 확인
sudo apache2ctl -S

# 오류 로그 확인
sudo tail -n 50 /var/log/apache2/web01-error.log
```

확인할 내용:
- Linux 파일 읽기 및 경로 탐색 권한
- Apache의 Require 접근 정책
- Directory 및 VirtualHost 설정

주의: 무조건 `chmod 777`을 사용하지 않는다.

### ② HTTP 404 Not Found

```bash
# 파일 존재 확인
ls -l /var/www/web01/public/

# DocumentRoot 확인
sudo grep -n 'DocumentRoot' \
  /etc/apache2/sites-available/web01.conf

# VirtualHost 확인
sudo apache2ctl -S
```

확인할 내용:
- 요청한 파일 존재 여부
- DocumentRoot 경로
- 다른 VirtualHost 선택 여부
- WAS로 전달되는 URL 경로

### ③ HTTP 502 / 503

WAS01에서 실행:

```bash
sudo ss -lntp '( sport = :8080 )'
```

WEB01에서 실행:

```bash
# WEB → WAS TCP 연결 검사
nc -vz -w 3 192.168.111.142 8080

# WAS 직접 HTTP 요청
curl -i http://192.168.111.142:8080/

# Apache를 통한 WAS 요청
curl -i -H "Host: web01.test" \
  http://127.0.0.1/app/

# Apache 프록시 오류 확인
sudo tail -n 50 /var/log/apache2/web01-error.log
```

핵심:
- WAS 직접 요청 실패 → WAS 및 네트워크 조사
- WAS 직접 요청 성공, 프록시 요청 실패 → Apache Proxy 설정 및 로그 조사

## 4. Apache 응답 지연 분석

```bash
# 활성 MPM 확인
apache2ctl -M | grep mpm

# CPU 처리 단위
nproc

# 메모리 사용량
free -h

# Apache 프로세스 자원 사용량
ps -C apache2 -o pid,ppid,%cpu,rss,cmd
```

MPM 관련 경고 확인:

```bash
sudo grep -Ei 'MaxRequestWorkers|server reached' \
  /var/log/apache2/error.log
```

확인할 내용:
- CPU 및 메모리 부족
- MPM 작업 처리 한도
- WAS 응답 지연
- DB 처리 지연

**응답이 느리다고 MaxRequestWorkers를 무조건 증가시키지 않는다.**

---

## 5. 로그를 활용한 장애 분석

### Access Log

```bash
sudo tail -n 50 /var/log/apache2/web01-access.log
```

확인:
- 어떤 URL을 요청했는가?
- 어떤 HTTP 상태 코드가 발생했는가?
- 언제 문제가 발생했는가?

### Error Log

```bash
sudo tail -n 50 /var/log/apache2/web01-error.log
```

확인:
- Apache 설정 및 접근 오류
- WAS 연결 거부
- 연결 타임아웃
- Reverse Proxy 오류

**Access Log = 장애 현상 확인**
**Error Log = 원인 분석 단서 확인**

---

## 6. 장애 복구 후 최종 검증

WEB01에서 실행한다.

```bash
# Apache 서비스 확인
systemctl is-active apache2

# 설정 문법 확인
sudo apache2ctl configtest

# 포트 확인
sudo ss -lntp '( sport = :80 )'

# 정적 페이지 확인
curl -i -H "Host: web01.test" \
  http://127.0.0.1/

# Reverse Proxy 확인
curl -i -H "Host: web01.test" \
  http://127.0.0.1/app/

# 오류 로그 확인
sudo tail -n 30 /var/log/apache2/web01-error.log
```

Apache가 실행 중이라는 사실만으로 서비스가 정상이라고 판단하지 않는다.

정적 페이지와 WAS 연동 요청까지 검증해야 한다.

---

## 7. 최종 핵심 정리

1. Apache 시작 실패 → systemctl, configtest, ss, journalctl
2. 403 → Linux 권한, Directory 접근 정책
3. 404 → 파일 존재 여부, DocumentRoot, VirtualHost
4. 502/503 → WAS 실행 상태, WEB→WAS 연결, Proxy 로그
5. 응답 지연 → MPM, CPU, 메모리, WAS·DB 처리 시간
6. 장애 발생 시 Access Log와 Error Log를 함께 확인한다.
7. 원인을 수정한 뒤 반드시 HTTP 요청으로 복구를 검증한다.

### 반드시 기억할 장애 대응 순서

**서비스 상태 → 포트·설정 → HTTP 응답 → 로그 분석 → 원인 해결 → 재검증**

### 핵심 문장

**장애 대응은 무조건 서버를 재시작하는 것이 아니라, 정상인 구간과 비정상인 구간을 구분하고 원인을 해결하는 과정이다.**
