
# A과정 4장 3교시 — WEB·WAS·DB 연동 및 장애 대응

## 1. 실습 환경

| 서버 | IP | 역할 | 포트 |
|---|---|---|---|
| WEB01 | 192.168.111.147 | Apache | 80 |
| WAS01 | 192.168.111.148 | Spring Boot | 8080 |
| DB01 | 192.168.111.149 | MySQL | 3306 |

- WAS 서비스: marble.service
- 애플리케이션: /opt/marble/app.jar
- 실행 계정: marble
- DB 환경변수: DB_HOST=192.168.111.149

## 2. 3-Tier 요청 처리 원리

```text
사용자
  ↓ HTTP :80
WEB01 (Apache)
  ↓ Reverse Proxy / HTTP :8080
WAS01 (Spring Boot)
  ↓ JDBC / MySQL :3306
DB01 (MySQL)
  ↓ 데이터 반환
WAS01 (HTTP 응답 생성)
  ↓
WEB01 → 사용자
```

### 서버별 역할

- WEB: HTTP 요청 수신 및 WAS로 전달
- WAS: 비즈니스 로직 실행, DB 연결
- DB: 데이터 저장 및 조회

**WEB 정상 ≠ WAS 정상 ≠ DB 정상**

각 구간을 별도로 검증해야 한다.

---

## 3. Spring Boot DB 연결 설정

기존 marble.service 설정:

```ini
Environment="DB_HOST=192.168.111.149"
```

Spring Boot JDBC 설정 예시:

```properties
spring.datasource.url=jdbc:mysql://${DB_HOST}:3306/marble
```

- DB_HOST: DB 서버 주소
- 3306: MySQL 수신 포트
- /marble: 예시 데이터베이스 이름

주의: JDBC 설정은 예시이며 실제 app.jar 설정과 다를 수 있다.

환경변수가 존재해도 애플리케이션이 이를 사용하지 않으면 DB 연결에 반영되지 않는다.

## 4. WAS01 정상 동작 검증

WAS01에서 실행:

```bash
# Spring Boot 서비스 상태
systemctl is-active marble

# Java 프로세스 확인
ps -ef | grep '[j]ava'

# TCP 8080 LISTEN 확인
sudo ss -lntp '( sport = :8080 )'

# HTTP 응답 확인
curl -i http://127.0.0.1:8080/health
```

### 확인 목적

| 명령어 | 확인 내용 |
|---|---|
| systemctl | Spring Boot 실행 상태 |
| ps | Java 프로세스 존재 여부 |
| ss | TCP 8080 수신 상태 |
| curl | 실제 HTTP 응답 |

/health가 구현된 경우 HTTP 200 응답을 확인한다.

## 5. WEB01 → WAS01 연결 검증

WEB01에서 실행:

```bash
# TCP 연결 확인
nc -vz -w 3 192.168.111.148 8080

# WAS 직접 HTTP 요청
curl -i http://192.168.111.148:8080/health
```

### 주요 옵션

- nc -v: 상세 출력
- nc -z: 포트 연결 검사
- nc -w 3: 최대 3초 대기
- curl -i: HTTP 응답 헤더와 본문 출력

### Apache 경유 확인

Apache ProxyPass 설정 예시:

```apache
ProxyPass "/app/" "http://192.168.111.148:8080/"
ProxyPassReverse "/app/" "http://192.168.111.148:8080/"
```

WEB01에서 실행:

```bash
curl -i -H "Host: web01.test" \
  http://127.0.0.1/app/health
```

경로 변환:

```text
/app/health → /health
```

실제 Apache 설정이 다른 경우 활성 VirtualHost와 ProxyPass 경로를 먼저 확인한다.

## 6. WAS01 → DB01 연결 검증

### ① TCP 3306 연결 확인 — WAS01

```bash
nc -vz -w 3 192.168.111.149 3306
```

TCP 연결이 가능하다는 것만 확인한다.

### ② MySQL 상태 확인 — DB01

```bash
sudo systemctl status mysql --no-pager

sudo ss -lntp '( sport = :3306 )'

sudo ufw status verbose
```

확인할 내용:
- MySQL 서비스 실행 여부
- TCP 3306 수신 여부
- bind-address 설정
- 방화벽 허용 여부

### ③ MySQL 로그인 확인 — WAS01

MySQL 클라이언트와 접속 정보가 있는 경우:

```bash
mysql -h 192.168.111.149 -P 3306 -u DB사용자 -p
```

로그인 후:

```sql
SELECT 1;
```

### DB 검증 3단계

1. TCP 3306 연결 성공
2. MySQL 사용자 인증 성공
3. SQL 실행 성공

**TCP 연결 성공 ≠ DB 로그인 성공 ≠ SQL 실행 성공**

## 7. 애플리케이션의 실제 DB 사용 검증

WAS01에서:

```bash
sudo journalctl -u marble -n 100 --no-pager
```

확인할 내용:
- JDBC 연결 오류
- Communications link failure
- Access denied
- SQL 실행 오류

기존 애플리케이션에 /health/db가 구현된 경우:

```bash
curl -i http://127.0.0.1:8080/health/db
```

또는 실제 DB 조회 API를 실행하여 데이터가 정상 반환되는지 확인한다.

주의: 단순 /health의 HTTP 200 응답은 DB 정상 연결을 보장하지 않는다.

## 8. 주요 장애 대응

### ① Apache /app/ 요청에서 502·503 발생

WEB01에서:

```bash
nc -vz -w 3 192.168.111.148 8080

curl -i http://192.168.111.148:8080/health
```

WAS01에서:

```bash
systemctl is-active marble

sudo ss -lntp '( sport = :8080 )'

sudo journalctl -u marble -n 50 --no-pager
```

우선 확인:
- Spring Boot 실행 상태
- TCP 8080 수신 여부
- WEB→WAS 연결
- Apache ProxyPass 설정과 Error Log

### ② Spring Boot에서 MySQL 연결 실패

WAS01에서:

```bash
nc -vz -w 3 192.168.111.149 3306
```

DB01에서:

```bash
sudo systemctl status mysql --no-pager

sudo ss -lntp '( sport = :3306 )'
```

### MySQL 오류별 원인

| 증상 | 우선 확인 |
|---|---|
| Connection refused | MySQL 실행·수신 주소·포트 |
| Connection timed out | 방화벽 및 네트워크 |
| Access denied (1045) | 계정·비밀번호·호스트 권한 |
| Unknown database (1049) | DB 이름·존재 여부 |
| SQL 오류 | SQL 문법·테이블·권한 |

### ③ /health는 200인데 DB 조회 실패

가능한 원인:
- DB 연결 오류
- JDBC 설정 오류
- DB 계정 권한 부족
- 테이블 또는 컬럼 누락
- SQL 실행 오류

Apache보다 Spring Boot 로그와 DB 상태를 우선 확인한다.

## 9. 장애 구간 구분

| 정상 | 실패 | 점검 대상 |
|---|---|---|
| Apache 정적 페이지 | /app/ | Reverse Proxy·WAS |
| WAS 직접 HTTP | Apache 경유 HTTP | VirtualHost·ProxyPass |
| WAS /health | DB 연결 | MySQL·JDBC·방화벽 |
| DB TCP 연결 | DB 로그인 | 계정·비밀번호·호스트 권한 |
| DB 로그인 | 데이터 조회 | SQL·테이블·접근 권한 |

---

## 10. 반드시 기억할 핵심

1. WEB→WAS는 HTTP, WAS→DB는 MySQL 프로토콜을 사용한다.
2. WEB, WAS, DB 상태는 각각 검증해야 한다.
3. Spring Boot는 JDBC를 통해 MySQL에 연결한다.
4. DB_HOST는 외부에서 DB 주소를 전달하는 환경변수이다.
5. nc는 TCP 연결, curl은 HTTP 응답, mysql은 DB 인증과 SQL 실행을 검증한다.
6. /health가 정상이어도 DB 연결 장애가 있을 수 있다.
7. 장애 발생 시 정상인 구간과 비정상인 구간을 구분하여 원인을 좁힌다.

### 핵심 장애 대응 흐름

**WEB 응답 → WEB·WAS 연결 → WAS HTTP → WAS·DB 연결 → DB 인증·SQL → 전체 재검증**

### 반드시 기억할 문장

**3-Tier 장애 대응의 핵심은 서버 전체를 재시작하는 것이 아니라, 어느 계층에서 요청이 실패했는지 확인하는 것이다.**
