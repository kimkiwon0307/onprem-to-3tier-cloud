## 2. Spring Boot와 MySQL 연동

Spring Boot는 JDBC를 이용해 MySQL과 통신한다.

### JDBC란?

Java 프로그램이 데이터베이스에 연결하고 SQL을 실행하기 위한 표준 API이다.

### Connection Pool이란?

DB 연결을 매번 새로 생성하지 않고 기존 연결을 재사용하는 방식이다.

- DB 연결 생성 비용 감소
- 연결 재사용으로 효율 향상
- 동시 DB 연결 수 관리

### 기존 프로젝트 환경변수

```ini
Environment="DB_HOST=192.168.111.149"
```

Spring Boot가 해당 환경변수를 실제 JDBC 설정에서 참조해야 적용된다.

### DB 연결 검증

WAS01에서 실행:

```bash
# TCP 3306 연결 확인
nc -vz -w 3 192.168.111.149 3306

# MySQL 로그인
mysql -h 192.168.111.149 -P 3306 -u 실제_DB계정 -p
```

로그인 후:

```sql
SELECT 1;
```

**TCP 연결 성공 ≠ DB 인증 성공 ≠ SQL 실행 성공**

## 3. SQL 기본 명령어 — CRUD

| 명령어 | 역할 |
|---|---|
| INSERT | 데이터 삽입 |
| SELECT | 데이터 조회 |
| UPDATE | 데이터 수정 |
| DELETE | 데이터 삭제 |

### 실습용 DB 생성

DB01에서 MySQL 접속:

```bash
sudo mysql
```

기존 데이터베이스를 확인한다.

```sql
SHOW DATABASES;
```

실습용 DB가 존재하지 않는 것을 확인한 후 생성한다.

```sql
CREATE DATABASE a_course05_lab
CHARACTER SET utf8mb4;

USE a_course05_lab;
```

기존 프로젝트 DB가 아닌 별도 연습용 데이터베이스를 사용한다.

### 테이블 생성

```sql
CREATE TABLE lesson_items (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    qty INT NOT NULL
) ENGINE=InnoDB;
```

- AUTO_INCREMENT: ID 자동 증가
- PRIMARY KEY: 행 식별
- VARCHAR(50): 최대 50자 문자열
- NOT NULL: NULL 금지
- InnoDB: MySQL 스토리지 엔진

### 데이터 삽입

```sql
INSERT INTO lesson_items (name, qty)
VALUES
    ('Keyboard', 10),
    ('Mouse', 20),
    ('Monitor', 5);
```

### 조회

```sql
SELECT * FROM lesson_items;
```

### 수정

```sql
UPDATE lesson_items
SET qty = 12
WHERE id = 1;
```

### 삭제

```sql
DELETE FROM lesson_items
WHERE id = 3;
```

**UPDATE와 DELETE에서는 WHERE 조건을 반드시 확인한다.**

이번 실습의 최종 데이터:

| id | name | qty |
|---|---|---|
| 1 | Keyboard | 12 |
| 2 | Mouse | 20 |

## 4. mysqldump란?

MySQL의 테이블 구조와 데이터를 SQL 파일로 저장하는 논리 백업 도구이다.

### 백업 원리

```text
MySQL 데이터베이스
       ↓
    mysqldump
       ↓
SQL 백업 파일
(CREATE TABLE, INSERT INTO 등)
```

### 백업 명령어

DB01의 Linux 터미널에서 실행:

```bash
umask 077

sudo mysqldump \
  --single-transaction \
  --quick \
  --no-tablespaces \
  --set-gtid-purged=OFF \
  a_course05_lab > "$HOME/a_course05_lab.sql"
```

### 주요 옵션

| 옵션 | 역할 |
|---|---|
| --single-transaction | InnoDB의 일관된 스냅샷을 기준으로 백업 |
| --quick | 데이터를 순차적으로 읽어 메모리 부담 감소 |
| --no-tablespaces | 테이블스페이스 관련 정보 제외 |
| --set-gtid-purged=OFF | GTID 관련 전역 변경문을 백업 SQL에 포함하지 않음 |
| > | 명령어 출력을 파일에 저장 |
| umask 077 | 새 파일의 접근 권한 제한 |

주의:
- `--single-transaction`은 주로 InnoDB에 적합하다.
- 백업 중 테이블 구조 변경이 발생하지 않도록 주의한다.
- DB 복제와 백업은 서로 다른 기능이다.

## 5. 백업 파일 검증

```bash
# 파일 존재와 크기 확인
ls -lh ~/a_course05_lab.sql

# 빈 파일이 아닌지 확인
test -s ~/a_course05_lab.sql \
  && echo "Backup file OK"

# SQL 내용 확인
head -n 25 ~/a_course05_lab.sql
```

백업 파일에서 다음과 같은 SQL을 확인할 수 있다.

```sql
CREATE TABLE ...
INSERT INTO ...
```

**백업 파일이 존재한다고 복구에 성공한다는 보장은 없다.**

실제로 복원해서 검증해야 한다.

## 6. MySQL 백업 복원

원본 DB에 복원하지 않고 별도 DB를 생성한다.

### 복원용 DB 생성

```bash
sudo mysql
```

기존 DB 목록을 확인하고 `a_course05_restore`가 없을 때만 생성한다.

```sql
CREATE DATABASE a_course05_restore
CHARACTER SET utf8mb4;

EXIT;
```

### SQL 파일 복원

DB01 Linux 터미널에서 실행:

```bash
sudo mysql a_course05_restore \
  < "$HOME/a_course05_lab.sql"
```

- mysql: MySQL 클라이언트
- a_course05_restore: 복원 대상 DB
- <: SQL 파일을 입력으로 전달

### 복원 결과 검증

```bash
sudo mysql
```

```sql
-- 원본 데이터
SELECT * FROM a_course05_lab.lesson_items
ORDER BY id;

-- 복원 데이터
SELECT * FROM a_course05_restore.lesson_items
ORDER BY id;
```

행 개수 비교:

```sql
SELECT COUNT(*) FROM a_course05_lab.lesson_items;

SELECT COUNT(*) FROM a_course05_restore.lesson_items;
```

예상 결과: 두 DB 모두 2건.

원본과 복원 데이터가 일치하는지 확인한다.

## 7. 백업·복구 정상 판단 기준

1. mysqldump 명령어가 정상 종료되었는가?
2. 백업 파일이 존재하고 내용이 있는가?
3. 복원 대상 DB에 테이블이 생성되었는가?
4. 원본과 복원 데이터가 일치하는가?
5. 필요한 경우 복원 DB에서 애플리케이션 기능이 정상 작동하는가?

**백업 성공 ≠ 복구 성공**

## 8. 장애 대응

### ① mysqldump Access denied

가능한 원인:
- 백업 계정 권한 부족
- 계정 인증 오류
- 백업 대상 객체의 추가 권한 필요

확인:

```sql
SHOW GRANTS;
```

### ② 백업 파일 복원 실패

확인할 내용:
- SQL 파일 정상 생성 여부
- 복원 대상 DB 존재 여부
- CREATE·INSERT 권한
- 기존 테이블과 이름 충돌
- MySQL 버전 호환성

### ③ Spring Boot에서 DB 연결 실패

WAS01에서:

```bash
nc -vz -w 3 192.168.111.149 3306

sudo journalctl -u marble -n 100 --no-pager
```

DB01에서:

```bash
sudo systemctl status mysql

sudo ss -lntp '( sport = :3306 )'
```

확인 대상:
- MySQL 서비스 상태
- DB 수신 주소와 포트
- 네트워크 및 방화벽
- 계정·비밀번호·권한
- JDBC 연결 설정

## 9. 반드시 기억할 핵심

1. Spring Boot는 JDBC로 MySQL과 통신한다.
2. Connection Pool은 DB 연결을 재사용한다.
3. INSERT·SELECT·UPDATE·DELETE는 기본 데이터 처리 SQL이다.
4. mysqldump는 SQL 파일을 생성하는 논리 백업 도구다.
5. --single-transaction은 InnoDB 백업의 일관성을 위해 사용한다.
6. mysql DB명 < 백업.sql 명령어로 복원할 수 있다.
7. 백업 파일 생성 후 실제 복원과 데이터 비교까지 검증해야 한다.
8. 운영 데이터가 아닌 별도 DB에서 복구 실습을 진행한다.

### 반드시 기억할 두 문장

**DB 연결 성공 ≠ 실제 데이터 조회 성공**

**백업 파일 생성 성공 ≠ 데이터 복구 성공**
