
# A과정 7장 2교시 — NAT Gateway 핵심 정리

## 1. NAT Gateway란?

NAT Gateway는 Private Subnet의 서버가 외부 인터넷으로 통신을 시작하고 응답을 받을 수 있도록 주소를 변환하는 AWS 서비스이다.

### NAT Gateway가 필요한 이유

Private 서버도 외부 인터넷 접속이 필요할 수 있다.

- Ubuntu 패키지 업데이트
- 외부 API 호출
- GitHub 및 소프트웨어 다운로드

**Public NAT Gateway는 Private 서버의 외부 통신을 지원하지만, 인터넷에서 Private 서버로 새로운 연결을 직접 시작하도록 허용하지 않는다.**

---

## 2. IGW와 NAT Gateway 차이

| 구분 | IGW | Public NAT Gateway |
|---|---|---|
| 역할 | VPC와 인터넷 연결 | Private 서버의 외부 통신 |
| 위치 | VPC에 연결 | Public Subnet |
| 공인 IP | 직접 통신하는 리소스에 필요 | Elastic IP 사용 |
| 외부에서 새 연결 | 조건 충족 시 가능 | Private 서버로 직접 연결 불가 |

---

## 3. NAT Gateway 패킷 흐름

```text
Private WAS01
     ↓
Private Route Table
0.0.0.0/0 → NAT Gateway
     ↓
Public NAT Gateway
(출발지 주소 및 포트 변환)
     ↓
Public Route Table
0.0.0.0/0 → IGW
     ↓
Internet Gateway
     ↓
외부 인터넷 서버
```

응답 패킷은 반대 방향으로 돌아와 원래 WAS01에 전달된다.

외부 서버에서는 일반적으로 NAT Gateway에 연결된 Elastic IP가 출발지 공인 IP로 보인다.

---

## 4. Public / Private Route Table

### Public Route Table

```text
Destination       Target
10.0.0.0/16       local
0.0.0.0/0         IGW
```

### Private Route Table

```text
Destination       Target
10.0.0.0/16       local
0.0.0.0/0         NAT Gateway
```

- `local`: 같은 VPC 내부 통신
- `0.0.0.0/0 → IGW`: 인터넷 연결 경로
- `0.0.0.0/0 → NAT`: Private 서버의 외부 통신 경로

**Private Subnet에서 인터넷에 접속하려면 Private Route Table의 NAT 경로와 NAT가 위치한 Public Subnet의 IGW 경로가 올바르게 구성되어야 한다.**

단, 외부 통신이 필요 없는 Private DB Subnet은 NAT 경로 없이 운영할 수도 있다.

---

## 5. Marble 프로젝트 적용

### 네트워크 구성

- VPC: 10.0.0.0/16
- Public Subnet: 2개
- Private Subnet: 6개
- AZ: 2개

### 핵심 구분

**서비스 요청 흐름**

```text
인터넷 사용자
   ↓
Public ALB
   ↓
Private WEB
   ↓
Private WAS
   ↓
Private DB
```

**Private 서버의 외부 통신 흐름**

```text
Private WEB/WAS
   ↓
NAT Gateway
   ↓
IGW
   ↓
인터넷
```

ALB → WEB → WAS → DB처럼 같은 VPC 내부에서 이루어지는 통신에는 일반적으로 NAT Gateway가 필요하지 않다.

※ 실제 NAT Gateway 개수와 연결된 Subnet은 AWS 콘솔에서 확인해야 한다.

---

## 6. AWS 콘솔 검증

### NAT Gateway 확인

AWS 콘솔 → VPC → NAT gateways

- State: Available
- Connectivity type: Public
- VPC 및 Subnet
- Availability Zone
- Elastic IP 연결

### Route Table 확인

AWS 콘솔 → VPC → Route Tables

- Private Subnet에 NAT 경로가 적용되었는가?
- NAT가 위치한 Public Subnet에 IGW 경로가 있는가?
- 올바른 Subnet Association이 설정되었는가?

---

## 7. NAT Gateway 장애 대응

### 증상: Private WAS에서 인터넷 접속 실패

확인 순서:

1. DNS 조회가 정상인가?
2. Private Route Table에 NAT 경로가 있는가?
3. NAT Gateway가 Available 상태인가?
4. NAT가 위치한 Public Subnet에 IGW 경로가 있는가?
5. Security Group과 NACL이 통신을 허용하는가?
6. 외부 대상 서버와 서비스가 정상인가?

### 핵심 판단

- VPC 내부 통신 성공 + 외부 통신 실패
  → NAT 경로, DNS, 외부 통신 정책 등을 우선 확인

- VPC 내부 통신도 실패
  → local 경로, Security Group, NACL, 대상 서비스 등을 확인

**NAT Gateway가 Available이어도 Route Table 설정이 잘못되면 인터넷 통신이 실패할 수 있다.**

---

## 8. NAT Gateway 1개 vs AZ별 구성

| 구분 | NAT 1개 | AZ별 NAT |
|---|---|---|
| 비용 | 상대적으로 낮음 | 상대적으로 높음 |
| 가용성 | NAT 장애 영향 범위가 큼 | AZ별 장애 영향 분리 |
| 적합한 상황 | 비용 중심 실습 환경 | 가용성 중심 운영 환경 |

NAT Gateway는 시간 및 데이터 처리량 등에 따른 비용이 발생한다.

---

## 9. 반드시 기억할 핵심

1. IGW는 VPC와 인터넷을 연결한다.
2. Public NAT Gateway는 Private 서버의 외부 통신을 지원한다.
3. NAT Gateway는 Public Subnet에 배치하고 Elastic IP를 사용한다.
4. Private Route Table은 인터넷 목적지를 NAT로 전달한다.
5. NAT가 있는 Public Subnet은 IGW 경로가 필요하다.
6. VPC 내부 통신에는 일반적으로 NAT가 필요하지 않다.
7. NAT가 정상이어도 Route Table이 잘못되면 통신이 실패한다.

### 최종 암기 문장

**IGW = 인터넷 연결**

**NAT Gateway = Private 서버의 외부 통신**

**local = VPC 내부 통신**

**Private → NAT → IGW → 인터넷**

**장애 대응 = DNS → Private Route Table → NAT → Public Route Table → SG/NACL → 대상 서비스**
