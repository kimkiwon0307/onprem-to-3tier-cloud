# 17장 2교시 — Jenkins + GitHub Poll SCM 구축

## 1. 학습 목표

AWS EC2에 Jenkins를 구축하고 GitHub Private Repository와 연결한다.

**Poll SCM을 이용해 GitHub에 새로운 Commit이 발생하면 Jenkins Job이 자동으로 실행되도록 구성한다.**

- 도메인 사용 X
- Webhook 사용 X
- Caddy 사용 X
- Poll SCM 사용 O

---

## 2. Poll SCM이란?

Poll SCM(Poll Source Code Management)은 Jenkins가 Git 저장소의 변경 사항을 주기적으로 확인하는 기능이다.

```text
Jenkins
   |
   | 약 5분 간격으로 GitHub 확인
   v
GitHub
   |
   +-- 변경 없음 → 빌드하지 않음
   |
   +-- 새 Commit → Jenkins Job 실행
```

### Webhook과 Poll SCM의 차이

| 구분 | Webhook | Poll SCM |
|---|---|---|
| 통신 시작 | GitHub → Jenkins | Jenkins → GitHub |
| 외부 수신 주소 | 필요 | 불필요 |
| 도메인 | 필수 아님 | 불필요 |
| 변경 감지 | 이벤트 기반 | 주기적 확인 |
| Marble 적용 | 미사용 | **사용** |

**선택 이유:** 별도의 외부 HTTPS Webhook 수신 환경 없이 GitHub 변경 사항에 따른 자동 실행을 구현하기 위해서이다.

## 4. AWS Jenkins EC2 구성

| 항목 | 설정 |
|---|---|
| Name | `marble-jenkins` |
| OS | Ubuntu 24.04 |
| Instance Type | `t3.medium` 권장 |
| VPC | `10.0.0.0/16` |
| Subnet | Public-A `10.0.1.0/24` |
| Public IP | 할당 |
| Storage | 40~50GiB 권장 |
| Jenkins Port | TCP 8080 |
| 관리자 접속 | SSH 터널 |

### Security Group

- Inbound TCP 22: 관리자 IP만 허용
- Inbound TCP 8080: 인터넷 접근 차단
- Inbound TCP 80/443: Webhook용 개방 불필요
- Outbound: GitHub 및 패키지 저장소 접속 허용

**핵심:** Poll SCM은 Jenkins가 GitHub로 접속하므로 외부에서 Jenkins에 접근할 필요가 없다.

## 5. Jenkins 설치 핵심 명령어

### ① Java 21 설치

```bash
sudo apt update
sudo apt install -y fontconfig openjdk-21-jre

```

### ② Jenkins 공식 저장소 등록

```bash

sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key
```

```bash
cd /etc/apt/sources.list.d/
sudo nano jenkins.list
```

입력:

```text
deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/
```

### ③ Jenkins 및 Git 설치

```bash
sudo apt update
sudo apt install -y jenkins git
```

### ④ 설치 검증

```bash
sudo systemctl status jenkins
sudo ss -lntp | grep ':8080 '
curl -I http://127.0.0.1:8080/login
git --version
```

| 명령어 | 확인 사항 |
|---|---|
| `systemctl status` | Jenkins 실행 상태 |
| `ss -lntp` | TCP 8080 LISTEN |
| `curl -I` | HTTP 응답 |
| `git --version` | Git 설치 |

## 6. Jenkins 관리자 접속

외부에 8080 포트를 공개하지 않고 SSH 터널을 이용한다.

관리자 PC에서 실행:

```bash
ssh -i marble-key.pem \
  -L 18080:127.0.0.1:8080 \
  ubuntu@JENKINS_PUBLIC_IP
```

브라우저 접속:

```text
http://127.0.0.1:18080
```

초기 관리자 암호 확인:

```bash
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
```

## 7. GitHub Private Repository 연동

Repository:

```text
https://github.com/kimkiwon0307/marble_project.git
```

Branch:

```text
master
```

### GitHub PAT 발급

GitHub에서 Fine-grained Personal Access Token을 생성한다.

- Repository: Marble 프로젝트만 선택
- Contents: Read-only
- Metadata: Read-only
- 만료 기간 설정

### Jenkins Credentials 등록

경로:

`Manage Jenkins → Credentials → Add Credentials`

| 항목 | 설정 |
|---|---|
| Kind | Username with password |
| Username | GitHub 사용자명 |
| Password | GitHub PAT |
| ID | `github-marble-read` |

**핵심:** PAT를 Jenkinsfile이나 Shell에 직접 작성하지 않고 Credentials로 관리한다.

## 9. Poll SCM 설정

경로:

`Jenkins Job → Configure → Build Triggers → Poll SCM`

Schedule:

```text
H/5 * * * *
```

### 설정 의미

| 표현 | 의미 |
|---|---|
| `H/5` | 약 5분 간격으로 검사 시점을 분산 |
| `*` | 모든 시간 |
| `*` | 모든 날짜 |
| `*` | 모든 달 |
| `*` | 모든 요일 |

**주의: 5분마다 빌드하는 것이 아니라 5분마다 변경 사항을 확인한다.**

변경 사항이 없다면 빌드하지 않는다.

### 자동 실행 확인

1. Jenkins에서 기존 Commit을 수동 빌드
2. GitHub `master`에 테스트 Commit 생성
3. 다음 Poll SCM 검사에서 변경 감지
4. Jenkins Job 자동 실행
5. Console Output에서 Commit ID와 SUCCESS 확인

예상 로그:

```text
Started by an SCM change
Checking out Revision ...
Finished: SUCCESS
```

## 10. 장애 대응

| 장애 | 원인 후보 | 확인 방법 |
|---|---|---|
| Jenkins 실행 안 됨 | Java·서비스 오류 | `systemctl`, `journalctl` |
| GitHub 연결 실패 | 네트워크·DNS | `curl`, `ip route` |
| Git 인증 실패 | PAT·Credentials | Console Output |
| Checkout 실패 | Repository·Branch 오류 | Git 설정 |
| 자동 실행 안 됨 | Poll SCM 미설정·변경 없음 | Build Triggers, Polling Log |
| 변경 없이 계속 빌드 | 다른 Trigger 활성화 | Job 설정 |

### 기본 장애 분석 순서

```text
1. Jenkins 서비스 상태
          ↓
2. GitHub HTTPS 접근
          ↓
3. Credentials 인증
          ↓
4. Git Checkout
          ↓
5. Poll SCM 설정
          ↓
6. 새로운 Commit 감지
          ↓
7. Console Output 확인
```

## 11. 최종 핵심 요약

1. Jenkins는 CI/CD 작업을 자동화하는 서버이다.
2. Poll SCM은 Jenkins가 GitHub의 변경 사항을 주기적으로 확인하는 기능이다.
3. `H/5 * * * *`는 약 5분 간격의 변경 검사 설정이다.
4. 변경 사항이 없으면 빌드하지 않는다.
5. GitHub Private Repository는 PAT 인증이 필요하다.
6. PAT는 Jenkins Credentials로 관리한다.
7. Jenkins 관리자 화면은 SSH 터널로 접속한다.
8. Poll SCM은 도메인·Webhook·Caddy 없이 사용할 수 있다.
9. 자동 실행 확인은 새로운 Commit ID와 Build History로 검증한다.
10. 이후 Gradle CI와 WAS CD를 연결해 자동 배포로 확장할 수 있다.

### Marble 프로젝트에서 Poll SCM을 선택한 이유

> Jenkins가 GitHub 저장소의 변경 사항을 주기적으로 확인하도록 구성하여, 별도의 외부 Webhook 수신 서버나 도메인 없이 CI 자동 실행을 구현하기 위해 Poll SCM을 선택했다.

### 최종 결론

**GitHub에 새로운 Commit이 발생하면 Jenkins가 Poll SCM으로 변경을 감지하고 자동으로 Job을 실행한다. 이후 Gradle Build/Test와 WAS01/02 배포 단계를 연결해 Marble CI/CD 파이프라인을 완성할 수 있다.**
